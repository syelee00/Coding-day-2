PRD — 오늘 뭐 먹지? (AI 메뉴 추천)
1. 제품 개요
사용자가 현재 상황을 간단히 입력하면, Gemini AI가 오늘 먹기 좋은 메뉴 3개와 이유·어울리는 음료를 추천하는 1페이지 웹 서비스.
- 목표: “뭘 먹을지” 고민하는 시간을 1분 이내로 줄인다.
- 타깃: 혼밥·친구·연인과의 식사 메뉴를 빠르게 정하고 싶은 사용자
- 성공 기준: 입력 완료 후 10초 이내에 납득 가능한 메뉴 3개를 확인할 수 있다.
2. MVP 범위
화면 1 — 조건 입력 폼
사용자는 아래 조건을 입력하고 메뉴 추천받기를 누른다.
항목	입력 방식	예시
기분	선택 칩	든든하게, 가볍게, 스트레스 해소, 특별하게
예산	선택 칩	1만 원 이하, 1~2만 원, 2만 원 이상
함께 먹는 사람	필수 선택	혼밥, 친구, 연인
못 먹는 음식	텍스트 입력	해산물, 매운 음식, 고수
어제 먹은 음식류	선택 칩	한식, 중식, 양식, 일식, 분식, 없음/기억 안 남
식사 환경	필수 선택	야외, 실내


- 필수값: 함께 먹는 사람, 식사 환경
- 선택값 미입력 시: AI가 일반적인 조건으로 보완해 추천
- 로딩 중: 버튼 비활성화 및 “오늘의 메뉴를 고민 중이에요…” 표시
- 오류 시: “추천을 불러오지 못했어요. 다시 시도해 주세요.”와 재시도 버튼 표시
화면 2 — AI 결과
AI 추천 결과를 카드 3개로 표시한다.
각 카드 구성:
- 메뉴명
- 추천 이유: 사용자가 입력한 조건을 반영한 1~2문장
- 어울리는 음료 1개
- 메뉴 유형 태그: 한식 / 중식 / 양식 등
하단 액션:
- 다시 추천받기: 조건 입력 화면으로 이동
- 조건 수정하기: 기존 입력값을 유지한 채 입력 화면으로 이동
3. AI 동작 및 응답 규칙
Gemini API에 사용자 조건과 아래 제약을 함께 전달한다.
- 서로 다른 메뉴 3개를 추천한다.
- 못 먹는 음식은 절대 포함하지 않는다.
- 어제 먹은 음식류와 같은 계열은 가급적 피한다.
- 예산·동반자·야외/실내 조건을 반영한다.
- 각 추천 이유는 구체적이고 짧게 작성한다.
- 한국어로 응답한다.
- 화면 안정성을 위해 JSON만 반환한다.
응답 예시:
{
  "recommendations": [
    {
      "name": "얼큰한 순두부찌개",
      "category": "한식",
      "reason": "스트레스를 풀고 싶은 기분에 잘 맞고, 혼자서도 부담 없이 든든하게 먹기 좋아요.",
      "drink": "식혜"
    }
  ]
}
4. 기술 설계
- Frontend: Next.js + App Router + TypeScript
- AI: Gemini API
- API Route: POST /api/recommend
- 상태 관리: React useState 수준의 로컬 상태만 사용
- 환경변수: GEMINI_API_KEY
- 보안: Gemini API 키는 서버 API Route에서만 사용하고 브라우저에 노출하지 않는다.
흐름: 입력 폼 → /api/recommend → Gemini API → 구조화된 결과 검증 → 결과 화면
5. Non-goals
이번 2시간 MVP에서는 만들지 않는다.
- 로그인·회원가입
- 추천 결과 저장, 히스토리, 즐겨찾기
- 위치 기반 맛집/배달앱 연동
- 지도, 식당 리뷰, 결제
- 개인화 학습 및 사용자 프로필
- 공유 기능
- 다국어 지원
- 복잡한 영양성분·알레르기 데이터베이스
- 추천 결과 재생성 외의 세부 필터링
6. 완료 기준
- 필수 조건을 입력해 추천 요청을 보낼 수 있다.
- Gemini가 메뉴 3개, 추천 이유, 음료를 반환한다.
- 결과가 카드 형태로 정상 표시된다.
- 로딩·API 오류 상태가 보인다.
- 모바일과 데스크톱에서 한 페이지 흐름이 깨지지 않는다.
